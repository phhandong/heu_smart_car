存储器分类标准

先问一个最实用的问题：断电以后，里面的数据还在不在？

  • RAM：断电后数据丢失，适合放正在使用、经常变化的数据。
  • ROM：断电后仍保留数据，适合放程序和需要保存的参数。

易失性存储器（RAM - Random Access Memory）

可以把 RAM 想成写作业时的草稿纸：计算中间结果、当前页号、光标位置，都可以随时改。单片机里的普通运行变量、数组，通常使用 RAM。

例如把一个变量从 20 改为 21，程序马上就能使用新值；但重新上电后，程序会按初始化代码或保存记录重新设置它，不能指望 RAM 自己记住 21。

RAM 的常见类型可以简单了解：

类型 通俗理解 常见用途
SRAM （静态RAM） 上电期间不需要周期刷新来保持数据 单片机运行内存、缓存
DRAM （动态RAM） 需要定期刷新，适合做较大容量的内存 电脑主内存，如 DDR

非易失性存储器（ROM - Read Only Memory）

ROM 的字面意思是“只读存储器”。Flash 也能断电保留数据，但它允许按规定擦除和重写，所以不要理解成“所有非易失存储器都不能修改”。本课主要使用的是单片机内部 Flash。

下面这些大致了解即可：

名称 怎样写入或修改
Mask ROM 制造时写好，之后不能修改
PROM 可以写入一次
EPROM 可用紫外线擦除后再写入
EEPROM 可以电擦除、电写入，通常支持较小单位的修改
Flash 可以电擦除、电写入，但擦除通常以一块区域为单位

我们下载到板子里的程序、希望断电保留的配置，都会占用非易失存储空间。

RAM 与 ROM

对比 RAM 本课使用的 Flash
断电后 运行数据丢失 已写入的数据保留
修改方式 可以频繁更新变量 要按擦除、写入规则操作
菜单中放什么 当前页面、光标、正在修改的参数 程序、已保存的参数

记住一个过程：开机从 Flash 读到 RAM → 运行中修改 RAM → 需要保存时写回 Flash。

第二部分：Flash 存储器详解

03

Flash 存储器概述

Flash 是一种断电仍能保留数据、可以重新擦写的存储器。可以把它想成保留正式结果的笔记本；但它不能像普通变量一样随意覆盖，每次修改都要遵守库函数的操作规则。

核心特点

  • 块擦除特性：按块或扇区进行擦除和写入（写入前需先擦除）
  • 有限寿命：擦写次数有限（SLC约10万次，MLC约1万次，TLC约1千次）
  • 速度特性：读取速度快（μs级），写入和擦除速度相对较慢（ms级）
  • 高集成度：单位面积存储密度高
  • 低功耗：待机功耗极低

Flash 类型分类

按存储单元分类

  • SLC（Single-Level Cell）：每个单元存储1位，速度快，寿命长，成本高
  • MLC（Multi-Level Cell）：每个单元存储2位，平衡性能与成本
  • TLC（Triple-Level Cell）：每个单元存储3位，容量大，成本低
  • QLC（Quad-Level Cell）：每个单元存储4位，超大容量，寿命较短

按组织和访问方式区分

  • NOR Flash：便于读取指定地址，常用于存放程序。
  • NAND Flash：通常按页读写、按块擦除，常用于大容量数据存储。

本次直接使用逐飞封装的片内 Flash 接口，不需要自己实现存储器控制器。

按键与 GPIO

GPIO 可以先理解成单片机可读写的引脚。本次把按键接到输入引脚：程序读取电平，得到按下或松开的状态。

本次采用上拉输入、按下接地的接法：未按下为高电平 1，按下为低电平 0。 这是由接线决定的，不是所有按键都一定低电平有效。

gpio_init(B14, GPI, GPIO_HIGH, GPI_PULL_UP); // PB14 设置为上拉输入
if (gpio_get_level(B14) == 0)              // 读取到低电平：按键处于按下状态
{
    // 后面还要消抖，并把一次按压转换成一次操作事件
}

按键抖动问题

按键是机械触点，刚按下或刚松开时，接触可能短暂不稳定。一次按压，程序可能读到 1 → 0 → 1 → 0，误以为按了好几次。

另外，就算没有抖动，手一直按着时，主循环也会反复读到 0。抖动和“保持按下被重复处理”是两个问题，都需要考虑。

消抖方法

硬件消抖

可通过合适的电阻、电容等电路减小电平跳动，需要结合电路设计。

软件消抖

方法 怎样做 本次是否采用
阻塞延时 发现按下后等一小段时间，再确认；等待松手后返回 采用，便于入门
主循环状态机 每次循环检查一点状态，不停在原地等待 留作课后拓展
周期扫描 按周期积累稳定状态，达到条件才产生事件 留作课后了解

消抖的重点是“确认状态稳定”，不一定都要调用延时函数。阻塞写法常先等约 10～20 ms，再检查一次。

简单延时法示例

下面是思路示例，不是可直接编译的 C 代码：

C 代码 · 9 行点击展开 / 收起
if (检测到按下)
{
    延时约 20 ms;
    if (仍然按下)
    {
        等待按键松开，并确认松开状态稳定;
        产生一次按键事件;
    }
}

加上“等待松手”，一次按压才不会在主循环里连续执行许多次。采用这个顺序时，操作在稳定松手后发生。

它的缺点很直接：等待期间程序停在这里，主循环中的屏幕刷新、模拟数据更新也会暂停。理解了这种简单写法后，再学习非阻塞方法会更容易。

按键模块只需要告诉菜单“上键、下键、左键、右键、确认键中的哪一个发生了”。至于上键如何移动光标、确认键进入哪个页面，由菜单模块决定。

菜单结构规划

写代码前，先把每个页面有什么选项、选中后做什么、怎样返回画清楚。不要一开始就把所有显示和按键判断堆在一起。

菜单通常要记住两件事：

  • level：现在在哪一层；简单示例中 0 为首页，1 为功能列表。
  • cur：光标选中第几项；数组编号从 0 开始，所以第一项是 0。

复杂菜单中，同一层可能有很多页面，这时可以另用 page 表示具体页面，并给不同页面保存自己的光标。层级只说明深度，页面编号才说明正在看哪一页。

整个主循环可以这样安排：

TEXT 代码 · 1 行点击展开 / 收起
读取并处理按键 → 根据按键修改菜单状态 → 根据新状态显示页面

下面用“工具列表：查看时间、设置闹钟”举例，只说明菜单组织方法，具体功能由对应函数实现。enter 表示按下确认，back 表示选中“返回”项后按确认，不要求增加一个专门的物理返回键。

方式一：if-else 逐层判断

C 代码 · 30 行点击展开 / 收起
func menu_ifelse()
{
    if (level == 0)                       // 当前在首页
    {
        if (enter)
        {
            cur = 0;                     // 刚进入列表时选中第一项
            level = 1;
        }
    }
    else if (level == 1)                  // 当前在工具列表
    {
        // 先根据上下键更新 cur，范围由当前列表的选项数量决定
        if (back)
        {
            level = 0;                   // 返回首页
        }
        else if (enter)
        {
            if (cur == 0)
            {
                打开查看时间的功能;
            }
            else if (cur == 1)
            {
                打开设置闹钟的功能;
            }
        }
    }
}

读法是：“先判断在哪一层，再判断按了什么，最后判断选中了哪一项”。具体功能页还需要自己设计返回逻辑，这里只展开首页和列表的分发思路。

特点： 写法直接，适合选项少时入门。页面越来越多时，判断分支也会增加；此时要把重复处理提成函数，避免同一段代码复制多次。if-else 本身并不难读，主要问题在于嵌套过深、职责混杂。

方式二：switch-case （函数指针与回调表分发）

这种写法把菜单分支判断和功能调用结合起来：用 switch-case 判断当前层级和选项，在对应的 case 中通过函数指针调用回调函数。

先理解三个概念：

  • 函数指针：普通指针可以指向变量，函数指针可以保存函数的地址。
  • 回调表：把各个功能的函数地址放进数组，数组中每一项对应一个菜单功能。
  • 回调函数：提前登记进表中的功能函数，在用户确认选项时，由菜单处理代码通过函数指针调用。

下面沿用前文的 level、cur、enter 和 back，这些变量由菜单与按键处理代码维护。两个功能函数只保留位置，具体功能需要自行实现。

C 代码 · 63 行点击展开 / 收起
#include <stddef.h>                      

typedef void (*Action)(void);


void show_time(void) { /* 查看时间的具体功能 */ }
void set_alarm(void) { /* 设置闹钟的具体功能 */ }

Action menu_actions[2] = {NULL, NULL};    // 回调表：保存两个功能的函数地址

void menu_init_callbacks(void)
{
    menu_actions[0] = show_time;          // 第 0 项登记查看时间的函数地址
    menu_actions[1] = set_alarm;          // 第 1 项登记设置闹钟的函数地址
    // 登记地址时没有执行函数；调用时才加 ()
}

void menu_switch_callback(void)
{
    switch (level)                       // 外层：判断当前菜单层级
    {
        case 0:                          // 首页
            if (enter)
            {
                cur = 0;                 // 进入列表时选中第一项
                level = 1;
            }
            break;

        case 1:                          // 工具列表
            // 先根据上下键更新 cur，再处理返回或确认
            if (back)
            {
                level = 0;               // 返回首页
            }
            else if (enter)
            {
                switch (cur)             // 内层：判断光标选中的功能
                {
                    case 0:
                        if (menu_actions[0] != NULL)
                        {
                            menu_actions[0](); // 通过函数指针调用查看时间
                        }
                        break;

                    case 1:
                        if (menu_actions[1] != NULL)
                        {
                            menu_actions[1](); // 通过函数指针调用设置闹钟
                        }
                        break;

                    default:
                        break;            // 无效选项不访问数组、不调用函数
                }
            }
            break;

        default:
            break;                        // 其他层级暂不处理
    }
}

两种方式对比

对比 if-else 逐层判断 switch-case 与函数指针回调表
确认后如何选择功能 用 if / else if 判断 cur 用 switch (cur) 进入对应 case
如何执行功能 在分支中编写处理或直接调用功能函数 在 case 中通过回调表里的函数指针调用功能
入门需要掌握 条件判断与分支顺序 switch-case、函数指针、回调与初始化
添加功能 增加相应判断与处理 增加 case、回调表项与初始化登记
容易出错的地方 分支漏写、状态切换混乱 漏写 break、指针未登记、选项与表项不对应
适合使用的时候 小菜单、先跑通基本逻辑 按编号分支，且希望各功能独立维护、方便更换

一、为什么要创建多个文件

1. 代码模块化

如果按键、显示、保存、菜单全部写在 main.c 中，想修改一个功能就要在长文件里反复查找。把功能分成模块，相当于把不同工具放进不同抽屉：要改按键就看按键模块，要改页面排版就看显示模块。

main.c 负责安排调用顺序，不负责实现所有细节。

2. 提高代码复用性

例如按键模块只返回按键事件，就能被不同菜单使用；显示模块负责屏幕排版，也不必知道 Flash 怎样擦写。以后更换硬件或增加功能时，修改范围会更清楚。

二、C 语言文件类型

文件 放什么 可以这样理解
.h 头文件 对外函数声明、类型、宏 告诉别人“这个模块能做什么、如何调用”
.c 源文件 函数实现、模块内部变量 写清“具体怎样做到”
